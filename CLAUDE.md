# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project goal

A native PC port (x86-64 Windows) of Super Mario Galaxy, in French, playable with an Xbox controller,
with optional enhancements. This repo is a private fork of the
[SMGCommunity/Petari](https://github.com/SMGCommunity/Petari) decompilation (branch `pc-port`).
The decomp build still rebuilds the original Wii `main.dol` byte for byte; the PC build compiles the
same C++ for x86-64 and replaces the Wii hardware/SDK with PC backends.

Target version: **RMGE01** (NTSC-U, includes French in `files/UsFrench`), because that's the disc
the user owns: `D:\SUPER_MARIO_GALAXY\Rom\Super Mario Galaxy (USA) (En,Fr,Es).rvz`. It is extracted
to `orig/RMGE01/` (gitignored). Never commit game data.

Upstream does not accept AI-generated contributions: keep everything in this fork, never open PRs.
The `upstream` remote has its push URL disabled. AstroCore (Luma's Workshop) is a separate,
unreleased PC port; don't copy from it.

Folder layout: this repo is `D:\SUPER_MARIO_GALAXY\Developpement`. Next to it: `Jeu\` (installed
game the user plays), `Rom\` (the RVZ), `References\` and `Outils_Claude\` (local helper scripts,
not in git; `vs.cmd` sets up MSVC + CMake + Ninja). Reference projects (read-only):
`D:\ZELDA_WINDWAKER_PC\Developpement` (the user's Wind Waker port, same approach, see its
CLAUDE.md), `D:\ZELDA_WINDWAKER_PC\References\{aurora,dusklight}` (Dusklight = Twilight Princess PC
port; its JSystem/JAudio2 PC changes are the best guide for ours).

## Commands (Windows)

Decomp (matching) build:
```
python configure.py --version RMGE01
python -m ninja            # must end with build/RMGE01/ok and main.dol SHA1 9a71008a...
```
Re-run the matching build after touching shared headers: PC changes must not break it.

PC build (MSVC 14.51 / VS 18, CMake + Ninja):
```
cmd //c "D:\SUPER_MARIO_GALAXY\Outils_Claude\vs.cmd cmake -S . -B build/pc -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo"
cmd //c "D:\SUPER_MARIO_GALAXY\Outils_Claude\vs.cmd cmake --build build/pc -- -k 0"
python tools/pc/compile_one.py src/Game/Foo/Bar.cpp     # one TU, safe in parallel
python tools/gen_pc_files.py                            # regenerate files.cmake from configure.py
```

## PC port architecture

- `CMakeLists.txt` builds one static library per configure.py library (lists in `files.cmake`,
  generated). Game libs, JSystem, nw4r are compiled; the Wii SDK (`src/RVL_SDK`), MSL, Runtime,
  MetroTRK, NDEV, NWC24, RVLFaceLib are not (host CRT + Aurora + pc/src replace them).
- Defines: `TARGET_PC=1 AVOID_UB=1 VERSION=1 RMGE01=1 ...`. Guard PC changes with `#if TARGET_PC`
  and keep the original code in the `#else` branch so the matching build is unaffected.
- `pc/include` comes first on the include path:
  - `pc_compat.h` is force-included: MSL/MWCC extensions (PPC intrinsics, `__va_list`, std:: float functions).
  - `revolution/*.h` shims map the Wii SDK onto Aurora's GameCube SDK (`dolphin/*`). Most are generated by
    `tools/pc/gen_rvl_shims.py`; "PC shim (manual)" ones are hand-written. Missing declarations go in
    `revolution/pc_extras/<area>.h`. Wii-only SDK headers (wpad, kpad, nand, sc, ...) fall through to
    `libs/RVL_SDK/include` and are implemented in `pc/src`.
  - `dolphin/types.h`: keeps `s32/u32` as `long/unsigned long` (the decomp mixes u32 and
    "unsigned long"; long is 32-bit on Windows).
  - `GXWGFifo.u8 = x` writes are redirected to Aurora's `GXCmd1u*` (pc_extras/gx.h).
- Aurora (`extern/aurora`, submodule pinned at the Wind Waker port's commit) + local patches in
  `pc/patches/aurora` (0001 = fixes from the Wind Waker port, 0002 = SDK struct/enum tags, 0003 = debug toggles + Z textures,
  0004 = strip/fan index reserve underflow that committed 8 GB, 0005 = supersampling VISetFrameBufferSupersample,
  0006 = GXPeekZ depth snapshot taken where the game peeks, not at the end of the frame), applied at
  configure time. `GXSetArray` on PC takes `(attr, data, size, stride, little_endian)`.
- `OPNEW_SIZE_T` = size type of operator new/delete (u32 on Wii, size_t on PC).
- Memory: plain `new` from the game libraries (code placed in section `.text$gb` by pc_compat.h,
  told apart by the return address in JKRHeap.cpp) allocates from the current JKRHeap like on the
  Wii, so objects go away with their scene heap; host code, template instantiations and threads
  without a heap get host memory. PC-only data that must outlive the current heap (caches,
  side tables freed on the next init) is allocated inside a `PcHostNewScope`. No `/OPT:ICF`.

## Porting rules (learned on Wind Waker, see its memory/CLAUDE.md)

- Never truncate pointers: `(u32)ptr` → `(uintptr_t)ptr` or pointer arithmetic. `/we4311 /we4302 /we4312` make it an error.
- Assets stay big-endian in memory: read file structures through BE wrappers / swaps (Dusklight's `BE(T)` pattern).
- Missing return values are errors (`/we4715 /we4716`): add `#if AVOID_UB return x; #endif`.
- bool functions cast to int-returning callbacks return garbage on x64; inline asm needs C fallbacks;
  3-vertex GX_QUADS must become triangles; ATTRIBUTE_ALIGN/NO_INLINE are empty on MSVC.
- NonMatching objects' C++ was never verified on hardware: suspect it first when behaviour is odd.
- Big-endian traps found so far: `#ifdef __MWERKS__` asm blocks with no `#else` (code vanishes on PC),
  u32 <-> RGBA color reinterpretation (must be 0xRRGGBBAA), bitmaps/octrees written as u16 and read
  as u32 (JKRUnitHeap, KCL), layouts that only worked because the Wii heap placed two `new`s next to
  each other, va_list copies (`va_copy`), worker/waiter races (the Wii is single-core with strict
  priorities: set state before waking the other thread).
- The PPC's integer division by zero doesn't trap: pc/src/crash_handler.cpp emulates it (quotient 0).

## Testing (PC)

- `SMGPC_INPUT` scripted input (pc/src/input/wiimote.cpp): `A@300,A@900+5,SHAKE@1200,STICKUP@1300+60,
  PTR-0.25:0.05@2500+700` (frames of KPADRead channel 0, optional +duration, PTR<x>:<y> places the
  pointer, -1..1). `SMGPC_START_STAGE=<Galaxy>[:scenario]` jumps there after loading a file.
- Diagnostics: `SMGPC_CONSOLE`, `SMGPC_LOG_FRAMES` (fps), `SMGPC_LOG_STATE`, `SMGPC_WATCHDOG=N`,
  `SMGPC_DUMP_THREADS=N`, `SMGPC_LOG_PLACEMENT`, `SMGPC_DEBUG_MTX`, `SMGPC_DEBUG_ASYNC`,
  `SMGPC_DEBUG_SPIN`, `SMGPC_TEST_MESSAGES`, `SMGPC_AUDIO_DUMP=out.wav`, `SMGPC_NO_AUDIO`,
  `SMGPC_NO_MOUSE`, `SMGPC_WII_ICONS`, `SMGPC_WINDOW_TITLE`, `SMGPC_LOG_MEMORY` (committed
  memory), `SMGPC_TRACE_BIG_ALLOC=<MB>` (stack of big malloc/realloc), `SMGPC_TRACE_HOST_NEW=<first>:<last>:<dump>`
  (game `new`s left in host memory and still alive), `SMGPC_HOST_NEW` (all plain `new` on the host), `SMGPC_DUMP_TEXTURES` (dumps to <user cache>/texture_dumps;
  Dolphin-format HD packs load from `textures/` next to the exe, same hashes as Dolphin), `SMGPC_BACKEND=d3d12|vulkan|d3d11`,
  `SMGPC_SUPERSAMPLE=N`, `SMGPC_LANGUAGE=fr|en|es` (display.ini: supersampling, langue); Aurora: `AURORA_DEBUG_NOCULL`,
  `AURORA_DEBUG_NODEPTH` (patch 0003).
- Local helper scripts (not in git) live in `D:\SUPER_MARIO_GALAXY\Outils_Claude`: `shots.ps1`
  (screenshots of a frozen copy of the build, without taking the focus), `sweep.ps1` (loads every
  galaxy and records crashes), `install.ps1` (copies the build to `..\Jeu` + desktop shortcut),
  `dolphin_shots.ps1` (reference renders with the portable Dolphin in `Outils_Claude\Dolphin`).
